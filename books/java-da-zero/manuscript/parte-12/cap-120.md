# Lezione 95. Immagini con i buildpacks e i layer

## Punti chiave

### Due strade per un'immagine

- Dockerfile: scriviamo noi ogni istruzione
- Cloud Native Buildpacks: il builder analizza il progetto
- ./mvnw spring-boot:build-image, nessun Dockerfile
- Builder e run image con versione precisa

> Percorso: Progetto Maven, poi Builder Paketo, poi Immagine OCI.

### Cosa fanno i buildpacks

- JRE Liberica scelta dalla versione Java del progetto
- Utente non root e distinta dei componenti (SBOM)
- Memoria della JVM calcolata all'avvio
- Layer riusati tra una build e l'altra

### I layer del Jar

- java -Djarmode=tools -jar app.jar list-layers
- dependencies, spring-boot-loader, snapshot-dependencies, application
- extract --layers: una cartella per layer
- Un COPY per layer: le dipendenze restano in cache

### Quale strada: KISS

- Buildpacks: immagine sensata senza mantenere un Dockerfile
- Dockerfile: controllo completo su base e contenuto
- Uno dei due per progetto, non entrambi
- Pochi kilobyte da ricostruire quando cambia il codice

`Dockerfile`

~~~dockerfile
FROM eclipse-temurin:25.0.4.1_1-jdk-noble AS build
WORKDIR /workspace
COPY mvnw pom.xml ./
COPY .mvn .mvn
RUN ./mvnw -B dependency:go-offline
COPY src src
RUN ./mvnw -B -o package -DskipTests
RUN java -Djarmode=tools -jar target/*.jar extract --layers --destination extracted
FROM eclipse-temurin:25.0.4.1_1-jre-noble
WORKDIR /app
COPY --from=build /workspace/extracted/dependencies/ ./
COPY --from=build /workspace/extracted/spring-boot-loader/ ./
COPY --from=build /workspace/extracted/snapshot-dependencies/ ./
COPY --from=build /workspace/extracted/application/ ./
ENV SERVER_ADDRESS=0.0.0.0 SERVER_PORT=8080
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "shop-0.0.1-SNAPSHOT.jar"]
~~~

## Comandi della lezione

I comandi che scriviamo nel terminale durante il video, nell'ordine.

~~~bash
./mvnw spring-boot:build-image
docker run --rm --name shop -p 127.0.0.1:18125:8080 -e SERVER_ADDRESS=0.0.0.0 -e SERVER_PORT=8080 shop:0.0.1-SNAPSHOT
java -Djarmode=tools -jar target/shop-0.0.1-SNAPSHOT.jar list-layers
docker build -t shop:layered .
docker history shop:layered
~~~

## Riepilogo

- spring-boot:build-image con builder e run image fissati
- jarmode tools: list-layers ed extract
- Quattro layer, dal più stabile al più variabile
- Lo strato dell'applicazione è l'unico che cambia spesso
