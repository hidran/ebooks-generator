# Lezione 98. Healthcheck, configurazione e segreti

## Punti chiave

### Tre problemi dello stack

- La password è scritta due volte nel file Compose
- E quel file finisce nel repository
- Cambiare un'impostazione non deve richiedere una build
- Docker non sa se lo Shop è pronto a rispondere

### Sonde e healthcheck

- Actuator: /actuator/health/liveness e /readiness
- HealthCheck usa la JRE già presente, nessuno strumento in più
- start_period e start_interval per l'avvio
- docker compose up -d --wait aspetta lo stato healthy

> Percorso: Docker, poi HealthCheck, poi /actuator/health/readiness.

### Prima e dopo: DRY

- Prima: la stessa password in due servizi
- Dopo: ${DB_PASSWORD} letto da .env, una sola fonte
- .env.example versionato con valori di prova, .env ignorato
- ${HEALTH_DETAILS:-never}: valore predefinito sicuro
- Compose secrets: file in /run/secrets, quando servono

`compose.yaml`

~~~yaml
services:
  app:
    build: .
    image: shop:config
    depends_on:
      db:
        condition: service_healthy
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://db:5432/shop
      SPRING_DATASOURCE_USERNAME: shop
      SPRING_DATASOURCE_PASSWORD: ${DB_PASSWORD:?set DB_PASSWORD in .env}
      MANAGEMENT_ENDPOINT_HEALTH_SHOW_DETAILS: ${HEALTH_DETAILS:-never}
    healthcheck:
      test: ["CMD", "java", "-cp", "shop-0.0.1-SNAPSHOT.jar", "com.shop.HealthCheck"]
      interval: 10s
      timeout: 5s
      start_period: 30s
      start_interval: 2s
      retries: 3
    ports:
      - "127.0.0.1:18128:8080"
  db:
    image: postgres:18.6-alpine3.24
    environment:
      POSTGRES_DB: shop
      POSTGRES_USER: shop
      POSTGRES_PASSWORD: ${DB_PASSWORD:?set DB_PASSWORD in .env}
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "shop", "-d", "shop"]

      timeout: 3s
~~~

`src/main/java/com/shop/HealthCheck.java`

~~~java
package com.shop;

import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.time.Duration;

public final class HealthCheck {
    private HealthCheck() {
    }

    public static void main(String[] args) throws InterruptedException {
        String port = System.getenv().getOrDefault("SERVER_PORT", "8080");
        URI uri = URI.create("http://127.0.0.1:" + port + "/actuator/health/readiness");
        HttpRequest request = HttpRequest.newBuilder(uri).timeout(Duration.ofSeconds(2)).build();
        try (HttpClient client = HttpClient.newHttpClient()) {
            HttpResponse<Void> response = client.send(request, HttpResponse.BodyHandlers.discarding());
            System.exit(response.statusCode() == 200 ? 0 : 1);
        } catch (IOException exception) {
            System.exit(1);
        }
    }
}
~~~

`src/test/java/com/shop/ProductApiTests.java`

~~~java
package com.shop;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.header;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc;
import org.springframework.http.MediaType;
import org.springframework.test.context.ActiveProfiles;
import org.springframework.test.web.servlet.MockMvc;

@SpringBootTest
@AutoConfigureMockMvc
@ActiveProfiles("test")
class ProductApiTests {
    @Autowired
    MockMvc mvc;

    @Test
    void listsTheDemoProducts() throws Exception {
        mvc.perform(get("/api/products"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$[0].name").value("Keyboard"))
                .andExpect(jsonPath("$[1].name").value("Mouse"));
    }

    @Test
    void createsAProduct() throws Exception {
        mvc.perform(post("/api/products").contentType(MediaType.APPLICATION_JSON)
                        .content("{\"name\":\"Monitor\",\"priceInCents\":18900}"))
                .andExpect(status().isCreated())
                .andExpect(header().exists("Location"))
                .andExpect(jsonPath("$.name").value("Monitor"));
    }

    @Test
    void rejectsAnInvalidProduct() throws Exception {
        mvc.perform(post("/api/products").contentType(MediaType.APPLICATION_JSON)
                        .content("{\"name\":\" \",\"priceInCents\":0}"))
                .andExpect(status().isBadRequest())
                .andExpect(jsonPath("$.type").value("https://api.shop.example/problems/validation-error"));
    }

    @Test
    void readinessProbeIsUp() throws Exception {
        mvc.perform(get("/actuator/health/readiness"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.status").value("UP"));
    }

    @Test
    void reportsAMissingProduct() throws Exception {
        mvc.perform(get("/api/products/999"))
                .andExpect(status().isNotFound())
                .andExpect(jsonPath("$.type").value("https://api.shop.example/problems/product-not-found"));
    }
}
~~~

## Riepilogo

- Configurazione dall'ambiente, nessuna nuova build
- Segreti fuori dal repository e fuori dall'immagine
- Readiness controllata da Docker con la JRE dell'immagine
- Un valore cambiato, solo il container dell'app ricreato
