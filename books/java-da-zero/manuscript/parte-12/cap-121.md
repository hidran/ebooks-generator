# Lezione 96. Immagini sicure

## Punti chiave

### Cosa può andare storto

- Il processo gira come root dentro il container
- Pacchetti inutili: più vulnerabilità da correggere
- File locali e segreti finiti nel contesto di build
- Vulnerabilità che non conosciamo finché non cerchiamo

### Un'immagine più sicura

- Base minima: JRE Temurin 25 su Alpine
- USER 10001:10001, un utente numerico non root
- ENTRYPOINT in forma exec: nessuna shell necessaria
- .dockerignore: .git, .idea, target, .env

> Percorso: JRE minima, poi Utente non root, poi Scansione.

### Segreti e scansione

- Mai password in ENV, ARG o file copiati: restano negli strati
- I segreti arrivano a runtime, dall'ambiente
- Trivy cerca vulnerabilità e segreti nell'immagine
- Database delle vulnerabilità scaricato prima, poi offline

## Codice della lezione

`Dockerfile`

~~~dockerfile
FROM eclipse-temurin:25.0.4.1_1-jdk-noble AS build
WORKDIR /workspace
COPY mvnw pom.xml ./
COPY .mvn .mvn
RUN ./mvnw -B dependency:go-offline
COPY src src
RUN ./mvnw -B -o package -DskipTests
RUN java -Djarmode=tools -jar target/*.jar extract --layers --destination extracted
FROM eclipse-temurin:25.0.4.1_1-jre-alpine-3.24
WORKDIR /app
COPY --from=build /workspace/extracted/dependencies/ ./
COPY --from=build /workspace/extracted/spring-boot-loader/ ./
COPY --from=build /workspace/extracted/snapshot-dependencies/ ./
COPY --from=build /workspace/extracted/application/ ./
USER 10001:10001
ENV SERVER_ADDRESS=0.0.0.0 SERVER_PORT=8080
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "shop-0.0.1-SNAPSHOT.jar"]
~~~

## Comandi della lezione

I comandi che scriviamo nel terminale durante il video, nell'ordine.

~~~bash
docker build -t shop:root .
docker run --rm --entrypoint id shop:root
docker build -t shop:secure .
docker run --rm --entrypoint id shop:secure
docker run --rm --name shop -p 127.0.0.1:18126:8080 shop:secure
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v trivy-cache:/root/.cache aquasec/trivy:0.76.0 image --quiet --skip-db-update --skip-java-db-update --severity HIGH,CRITICAL shop:secure | less
~~~

## Riepilogo

- Immagine runtime minima, senza strumenti di build
- Utente non root con UID numerico
- .dockerignore come protezione del contesto
- Scansione con Trivy prima di pubblicare l'immagine
